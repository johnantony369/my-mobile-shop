# Web App Version (/web/app) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a desktop/tablet-optimized web version of My Mobile Shop routed at `/web/app` with a persistent sidebar, wide ledger table, quick KPI cards, and full feature parity, while preserving the existing mobile `/app` experience and shared IndexedDB/Firebase backend.

**Architecture:** Create a dedicated desktop shell `WebApp.tsx` under `src/screens/web/` composed of `WebSidebar`, `WebHeader`, and responsive desktop views (`WebBookView`, `WebStockView`, `WebRepairsView`, `WebToolsView`, `WebSettingsView`). Wire `/web/app` and `/web/app/*` into `AppRouter.tsx` using `WebRouteWrapper` with identical authentication and cloud hydration guarantees.

**Tech Stack:** React 19, TypeScript, Tailwind CSS, Lucide React, Dexie IndexedDB (`dexie-react-hooks`), Firebase Auth & Firestore.

## Global Constraints
- Do NOT push to Git (`git push`) or deploy to Vercel (`vercel`) unless explicitly requested by the user in that prompt.
- Keep all existing mobile functionality intact on `/app`.
- Both `/app` and `/web/app` must use the same Dexie database tables and Firebase sync engine without schema drift.
- Verify everything with `npm test` and `npm run build`.
